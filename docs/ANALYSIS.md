# Разбор проекта AtentisConnector и что исправлено

Источник: `grigorievfinance/AtentisConnector` (версия 3.3.5, коммит `050713f`), прочитан целиком, **без изменений**.

## 1. Что делал старый проект

WinForms-приложение (.NET Framework 4.8, ~5 000 строк C#, «Alor / Atentis Alor Connector»):

1. Подключается к двум слотам торговой системы Atentis через `Atentis.Connection.dll`: **MICEX** (фондовый рынок, `SPOT`)
   и **FORTS** (срочный, `FUT`). Логины/пароли вводились в окне и сохранялись в `C:\AtentisData\settings.json`.
2. Получает таблицы `ORDERS, POSITIONS, SECURITIES, FIRM_HOLDING_TOTAL, TRADES`, показывает в `DataGridView`.
3. Сохраняет данные: ежедневные CSV-файлы, локальную SQLite (`C:\AtentisData\database\Database.db`); в коде также
   заготовки для PostgreSQL, ClickHouse и SQL Server (подключались/отключались правкой кода).
4. Считает **финрез** арбитража «спот–фьючерс» (`calculate/Calculate.cs`, `AltCalculate.cs`): сопоставляет сделки по
   тикеру, количеству (`counts.txt`), противоположной стороне и времени, считает спред и комиссии (`tickers.txt`, `counts.txt`).
5. Прочее: импорт XLSX-отчёта брокера, экспорт CSV, «сохранение по таймеру», окно настроек.

Работало только пока открыто окно приложения; после обрыва связи или падения его требовалось перезапускать вручную.

## 2. Найденные проблемы

### Безопасность

| # | Серьёзность | Где | Проблема | Как в AtentisServer |
|---|---|---|---|---|
| S1 | **Критично** | `ui/Main.cs` (закомментированная строка подключения), `service/CHService.cs` | В репозитории (и **в его истории**) учётные данные: хост, логин и пароль PostgreSQL, пароль ClickHouse. | Секретов в коде нет. **Старые пароли считать скомпрометированными и сменить** ([SECURITY.md](SECURITY.md)). |
| S2 | Высокая | `util/EncryptUtil.cs` | «Шифрование» `settings.json`: ключ и соль зашиты в код, IV выводится из того же ключа, нет аутентификации. Файл лежит в `C:\AtentisData` без ограничения прав. | Пароли только в переменных окружения службы (реестр, права Administrators/SYSTEM); никаких файлов с паролями. |

## 3. Что сделано

* **Финрез и все расчёты удалены**: `Calculate`, `AltCalculate`, `Deal/Unite`, `Tickers`, `counts.txt`/`tickers.txt`,
  импорт XLSX, UI, экспорт CSV, таймер. Осталось только: подключиться → получить таблицы → сохранить в PostgreSQL.
* **Служба Windows** (.NET Worker + `UseWindowsService`): автозапуск (отложенный), авто-перезапуск, виртуальная
  учётная запись `NT SERVICE\AtentisServer` с минимальными правами, штатная остановка. Ручных действий не требуется.
* **Надёжность**: реконнект и пересоздание слота, backoff, аварийный выход → перезапуск SCM, повторы записи при сбое БД,
  идемпотентная пакетная запись (`UNIQUE` + `ON CONFLICT`), пул соединений вместо одного общего, схлопывание обновлений.
* **Безопасность**: нет секретов в коде/файлах/логах, параметризованный SQL, валидация конфигурации при старте,
  метрики только на localhost по умолчанию, роль БД только для чтения для Grafana.
* **Логирование и мониторинг**: Serilog (текст + JSON, ротация, журнал Windows для WRN/ERR, троттлинг шума библиотеки),
  Prometheus-метрики, health-check, `atentis.collector_status` — [MONITORING.md](MONITORING.md).
* **Тесты**: 39 (мапперы, идемпотентность, реконнект/backoff, валидация, интеграция с реальным PostgreSQL).

## 4. Что не проверено

* Реальное подключение к серверу Atentis: у меня нет доступа к нему. Проверено, что библиотека загружается в .NET 10,
  подключение/пересоздание слота/логирование работают против заведомо недоступного адреса, а конвейер данных — на
  имитации слота и реальном PostgreSQL. **Первый запуск на сервере с реальными слотами нужно проверить вам** (см. чек-лист в README).
* Установочные PowerShell-скрипты и работа под Windows Server 2019: написаны по документации, на Windows не запускались
  (в среде разработки Windows нет). Сборка `win-x64` проверена.
* Ключевые поля `POSITIONS`/`FIRM_HOLDING_TOTAL` (`Collector:Tables:KeyFields`) выставлены по документации; если какого-то
  поля нет в вашем слоте, сервис напишет предупреждение и будет хранить каждое новое состояние строки.
