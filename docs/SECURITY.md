# Безопасность

## Сделать немедленно (по результатам разбора старого репозитория)

1. **Сменить пароли, найденные в `AtentisConnector`**: PostgreSQL (хост, логин и пароль были в закомментированной строке
   подключения в `ui/Main.cs`) и ClickHouse (`service/CHService.cs`). Они остаются в истории git, даже если репозиторий
   закрыт или архивирован. Если сервер PostgreSQL доступен из интернета — закрыть порт файрволом/VPN.
2. Если пароли Atentis когда-либо лежали в `C:\AtentisData\settings.json` — считать их известными всем, кто имел доступ к
   файлу и сборке (ключ зашит в код), и сменить у брокера.
3. Старый репозиторий после переезда архивировать и отозвать у Claude доступ — [MIGRATION.md](MIGRATION.md).

## Модель безопасности AtentisServer

| Область | Решение |
|---|---|
| Секреты | Только переменные окружения **службы** (`HKLM\SYSTEM\CurrentControlSet\Services\AtentisServer\Environment`, доступ Administrators/SYSTEM), записываются `Set-AtentisSecrets.ps1` через `SecureString`. В репозитории, `appsettings.json`, логах и метриках паролей нет (проверено тестом запуска: пароль не попадает ни в консоль, ни в файлы логов). |
| Учётная запись | Виртуальная `NT SERVICE\AtentisServer`: не пользователь, без пароля, права — чтение каталога программы и запись в `%ProgramData%\AtentisServer\logs`. |
| Конфигурация | `appsettings.local.json` лежит в `%ProgramData%\AtentisServer` (доступ Administrators/SYSTEM/служба). Валидируется при старте; в сообщениях об ошибках значений паролей нет. |
| База данных | Все значения — параметры Npgsql, SQL — константы (нет SQL-инъекций). Роль `atentis_app` владеет только БД `atentis`; Grafana и аналитики работают под `atentis_reader` (только `SELECT`). Для удалённой БД используйте `SSL Mode=VerifyFull`. |
| Atentis | Для защищённого соединения укажите `PublicKeyFile` (при пустом значении библиотека работает в **незащищённом** режиме). |
| Сеть | Порт метрик/health по умолчанию слушает только `127.0.0.1`. Для Prometheus на другом хосте: `Monitoring:Url=http://<ip>:9464` и правило Windows Firewall только для адреса Prometheus. Метрики не содержат персональных или торговых данных, но раскрывают версии и состояние. |
| Зависимости | Минимум: Npgsql, Serilog, prometheus-net, Microsoft.Extensions.*. Рекомендуется включить Dependabot и `dotnet list package --vulnerable` в CI (CI из репозитория делает это на каждый push). |
| Логи | Не содержат паролей и строк подключения. Содержат номера сделок/счетов в сообщениях уровня Debug — на проде уровень Information. Права на каталог логов — как у каталога данных. |
| Целостность данных | `UNIQUE`-ограничения и `ON CONFLICT DO NOTHING`: повторные/конкурентные записи не создают дублей; ошибки в данных Atentis приводят к пропуску строки с предупреждением, а не к остановке сбора. |

## Что осталось на вашей стороне

* Резервное копирование PostgreSQL (`pg_dump`/WAL-архив) и проверка восстановления.
* Обновления Windows Server и PostgreSQL; ограничение RDP/админских доступов.
* Ротация паролей: `Set-AtentisSecrets.ps1` → `Restart-Service AtentisServer`.
* Для Grafana — отдельная учётная запись с минимальными правами, HTTPS и смена пароля `admin`.
